— tags

Document Structure

<!DOCTYPE html> M1
The document type declaration. Always the very first line of every HTML file. Tells the browser this is modern HTML5 — not older HTML or XHTML. Not a tag — it's an instruction.
When: Always. Line 1 of every .html file. Never omit it.
<!DOCTYPE html>
<!-- Required. One per file, line 1. -->
<html> M1
The root element — wraps absolutely everything else on the page. The lang attribute tells browsers and screen readers what language the page is in.
Key Attribute
langLanguage code, e.g. "en". Used by screen readers and search engines.
When: Wraps the entire file — right after <!DOCTYPE>. One per page.
<html lang="en">
  <!-- head + body go here -->
</html>
<head> M1
The metadata container. Everything inside <head> is invisible to visitors — it holds information about the page: character encoding, title, linked stylesheets, etc.
When: Always the first child of <html>. Contains <meta>, <title>, <style>, <link>.
<head>
  <meta charset="UTF-8">
  <title>Page Title</title>
</head>
<meta> M1
A self-closing metadata tag. The most important use is charset="UTF-8" — without it, special characters (accents, emojis) may break. Also used for viewport, description, and more.
Common Attributes
charset"UTF-8" — always include this one
name / contentPaired for viewport, description, author, etc.
When: Inside <head>. At minimum: <meta charset="UTF-8">.
<meta charset="UTF-8">
<meta name="viewport"
      content="width=device-width">
<title> M1
Sets the browser tab text and is what search engines show as the clickable headline in results. The only visible use of the <head> section.
When: One per page, inside <head>. Best format: "Page | Site Name".
<title>Ada Lovelace | Portfolio</title>
<!-- Shows in browser tab + search results -->
<body> M1
The visible content container. Everything a visitor sees on the page — text, images, links, forms — lives inside <body>. Sibling to <head>, child of <html>.
When: Always. Contains all visible page content. One per page.
<body>
  <header>…</header>
  <main>…</main>
  <footer>…</footer>
</body>

Text & Lists

<h1> – <h6> M1
Heading tags. Describe structure, not size. <h1> is the single most important heading (your name on a portfolio). <h2> for sections, <h3> for sub-sections. Never skip levels.
Rule: Exactly one <h1> per page. Use CSS to change size, not different heading levels.
<h1>Ada Lovelace</h1>
<h2>About Me</h2>
<h3>My Interests</h3>
<!-- h4, h5, h6 for deeper sub-sections -->
<p> M1
A paragraph. The browser adds space above and below automatically. Use for any block of running text — about sections, descriptions, bios.
When: Any prose block. Don't use <br> between lines to fake paragraphs — use separate <p> tags.
<p>Hi, I'm Ada — an aspiring developer
learning to build for the web.</p>
<strong> M1
Marks text as important — renders bold, but the meaning is "this matters" not "make it big." Screen readers may announce it with emphasis. Use for genuinely important words, not decoration.
When: Key words that change meaning. Avoid using it just to make things look bigger — use CSS for that.
<p>Always add <strong>alt text</strong>
to every image.</p>
<em> M1
Marks text as emphasized — renders italic, but means "stress this in speech." Distinct from <i> which is purely visual italics. Screen readers change tone.
When: Words you'd stress out loud in speech: "I never skip alt text."
<p>This is <em>really</em> important.</p>
<blockquote> M1
A quoted block — set apart visually from normal text, usually indented. Use for mottos, pull-quotes, or longer cited text.
When: Quoting someone else's words at length, or featuring a personal motto. For short inline quotes use <q>.
<blockquote>
  <p>"The best way to predict the
  future is to <strong>build</strong> it."</p>
</blockquote>
<br> M1
A line break — forces text to the next line without starting a new paragraph. Self-closing. Use sparingly — if you need a paragraph gap, use a new <p>.
When: Addresses, poems, where a line break is part of the content. Not for spacing between paragraphs.
<p>123 Main Street<br>
Chennai, Tamil Nadu</p>
<hr> M1
A horizontal rule — a visual separator between sections. Self-closing. Represents a thematic break in content, not just a decorative line.
When: Separating major content blocks. Not for decoration — use CSS borders/dividers for that.
<h2>About Me</h2>
<p>…content…</p>
<hr>
<h2>My Roadmap</h2>
<ul> M1
An unordered (bulleted) list. Use when the items have no meaningful sequence — a skills list, a hobbies list, a features list.
When: Order doesn't matter. Skills, interests, features. Children must be <li> elements only.
<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>Problem solving</li>
</ul>
<ol> M1
An ordered (numbered) list. Use when sequence or ranking matters — steps in a process, a roadmap, a ranked list.
When: Order matters — instructions, steps, rankings. Same as <ul> but numbered automatically.
<ol>
  <li>Learn HTML</li>
  <li>Learn CSS</li>
  <li>Build a project</li>
</ol>
<li> M1
A list item. Always a direct child of <ul> or <ol>. Can contain text, other tags, or even a nested <ul>/<ol>.
When: Inside <ul> or <ol>. You can nest a full <ul> inside an <li> for sub-lists.
<ul>
  <li>Sports
    <ul>
      <li>Cricket</li>
      <li>Football</li>
    </ul>
  </li>
</ul>

Links

<a> — Page Link M2
The anchor tag — creates a clickable link. The href attribute is where the link goes. Can link to other pages, sections on the same page, email, or external sites.
Key Attributes
hrefThe destination URL or path. Required.
target"_blank" opens in a new tab. Omit for same tab.
idAdded to a heading/element so href="#id" can jump to it.
Rule: Use target="_blank" for external sites only. Internal links stay in the same tab.
<!-- Relative (same project) -->
<a href="about.html">About</a>

<!-- External, new tab -->
<a href="https://github.com/ada"
   target="_blank">GitHub</a>

<!-- Jump to section on same page -->
<a href="#skills">See my skills</a>
<h2 id="skills">Skills</h2>
<a> — Email & Phone M2
The same <a> tag, but with special href values. mailto: opens the visitor's email app. tel: opens the phone app on mobile devices.
Special href Values
mailto:href="mailto:you@email.com" — opens email app
tel:href="tel:+91XXXXXXXXXX" — opens dialer on mobile
When: Contact sections. Show the address as visible text too — some users copy-paste instead of clicking.
<a href="mailto:ada@example.com">
  Email Me
</a>

<a href="tel:+919876543210">
  Call +91 98765 43210
</a>

Images

<img> M2
Embeds an image. Self-closing. src points to the file; alt is the text shown when the image can't load and read aloud by screen readers. Never skip alt.
Attributes
srcPath to the image file. Required. Use a relative path like images/photo.jpg.
altDescriptive text. Required. Describe what a friend on the phone would need to hear.
width / heightOptional pixel size. Prefer CSS for layout; use these as hints for the browser to reserve space.
Rule: Organize images in an /images folder. A bad alt: alt="img1". Good alt: alt="Ada presenting to classmates".
<img
  src="images/profile.jpg"
  alt="Ada smiling in front of a whiteboard"
  width="200"
>

Semantic Layout

<header> M2
The top-of-page landmark. Contains your name/logo, an intro, and the <nav>. Screen readers and Google know this is the page header — unlike a <div>.
When: One per page, at the top. Contains your <h1> and <nav>. Never put main content here.
<header>
  <h1>Ada Lovelace</h1>
  <nav>…</nav>
</header>
<nav> M2
The navigation landmark. Wraps links that help users move around the site or page. Screen reader users can jump directly to the nav. Contains only links, not text paragraphs.
Rule: Only navigation links inside. Screen readers skip to it. Don't put paragraphs or headings inside <nav>.
<nav>
  <a href="index.html">Home</a>
  <a href="about.html">About</a>
  <a href="contact.html">Contact</a>
</nav>
<main> M2
The primary content landmark. The unique content of this page goes here — not the nav or footer. Screen readers have a "skip to main" shortcut that jumps directly here.
Rule: Exactly one per page. Never put repeated elements (nav, footer) inside it. Contains your sections.
<main>
  <section id="about">…</section>
  <section id="skills">…</section>
</main>
<section> M2
A thematic grouping of content. Each section should have its own heading. Use to group your About, Skills, Roadmap, Projects blocks — each one a distinct topic.
Common Attribute
idAdds a jump target: href="#skills" jumps here. Use for in-page nav links.
When: Grouping content that belongs together under a heading. Inside <main>. Use id to make it a jump target.
<section id="skills">
  <h2>Skills I'm Learning</h2>
  <ul>…</ul>
</section>
<aside> M2
Tangential content — related to the nearby content but not essential to it. Think sidebars, pull-quotes, fun facts, or "Did you know?" boxes.
When: Supplementary info that could be removed without breaking the main flow. Sidebars, callouts, fun facts.
<aside>
  <p>Fun fact: I can solve a Rubik's
  cube in under 2 minutes!</p>
</aside>
<footer> M2
The bottom-of-page landmark. Contains copyright, repeated contact links, social links. Screen readers identify it as the site footer.
When: Once per page, at the bottom. Use the HTML entity &copy; for the © symbol.
<footer>
  <p>&copy; 2026 Ada Lovelace</p>
  <a href="mailto:ada@email.com">
    Contact
  </a>
</footer>

Tables

<table> M3
The table container. Wraps all other table elements. Only use tables for actual tabular data — rows and columns of related information. Never use for layout.
Use for: Skills with levels, project lists, schedules, comparisons. Not for: navigation bars, page layout, image grids.
<table>
  <caption>My Projects</caption>
  <thead>…</thead>
  <tbody>…</tbody>
</table>
<caption> M3
A table title — displayed above the table, associated with it for screen readers. Makes the table's purpose immediately clear without needing a separate heading.
When: Always include one. Must be the first child inside <table>.
<table>
  <caption>Skills & Proficiency Levels</caption>
  …
</table>
<thead> / <tbody> M3
Groups rows into the header section (<thead>) and the body section (<tbody>). Browsers can repeat <thead> when printing long tables. Screen readers use it to announce column headers.
Rule: Always separate your header row into <thead>. Put all data rows in <tbody>.
<thead>
  <tr><th>Project</th><th>Status</th></tr>
</thead>
<tbody>
  <tr><td>Portfolio</td><td>In progress</td></tr>
</tbody>
<tr> M3
A table row. Contains <th> or <td> cells. Lives inside <thead> or <tbody>. One <tr> = one horizontal row.
When: Every row of data. The number of <td>/<th> cells should be the same across all rows.
<tr>
  <td>HTML</td>
  <td>Confident</td>
  <td>Module 1–4</td>
</tr>
<th> M3
A header cell. Rendered bold and centered by default. Screen readers announce the header when reading each row's data. Use in <thead> rows or as the first cell of each body row.
When: Column headings (inside <thead>). Also valid as the first cell of each row for row labels.
<thead>
  <tr>
    <th>Skill</th>
    <th>Level</th>
  </tr>
</thead>
<td> M3
A regular data cell. Goes inside <tbody> rows. This is the everyday workhorse — most cells in a table are <td>.
When: Every data cell in the body of the table. Can contain text, images, links, or other HTML.
<tr>
  <td>CSS</td>
  <td>Learning</td>
</tr>

Forms

<form> M3
The form container. Wraps all inputs, labels, and buttons. Without a backend, clicking Submit won't send anything — but the structure is the same.
When: Any time you collect user input — contact forms, sign-ups, searches. All form fields go inside.
<form>
  <fieldset>…labels & inputs…</fieldset>
  <button type="submit">Send</button>
</form>
<fieldset> / <legend> M4
<fieldset> groups related fields; <legend> is its caption. Screen readers announce the legend before reading each field inside the group — vital for accessibility.
When: Grouping related fields together ("Your Details", "Your Message"). Use 2+ fieldsets in any form with more than 3 fields.
<fieldset>
  <legend>Your Details</legend>
  <label for="name">Name</label>
  <input type="text" id="name">
</fieldset>
<label> M3
Associates a text description with an input. When for matches the input's id, clicking the label focuses the field — and screen readers read the label when the field is focused. Never skip labels.
Key Attribute
forMust match the id of the associated input. Required for accessibility.
Rule: Every input needs a label. for on the label must match id on the input — exactly.
<label for="email">Email Address</label>
<input type="email" id="email"
       name="email">
<!-- for="email" ↔ id="email" ✓ -->
<input> M3
The most versatile form element — changes completely based on its type. Self-closing. Handles text, email, passwords, checkboxes, radio buttons, dates, file uploads, and more.
Key Attributes
type"text" "email" "password" "checkbox" "radio" "date" "file"
idLinks to a <label for>. Required for accessibility.
nameUsed to identify the field when the form is submitted to a server.
requiredBrowser blocks submission if this field is empty. No JS needed.
minlengthMinimum number of characters allowed.
maxlengthMaximum number of characters allowed.
patternA regex the value must match, e.g. "[0-9]{6}" for a 6-digit PIN.
placeholderHint text shown when the field is empty. Not a replacement for labels.
Rule: Use type="email" for email fields — the browser validates the @ for free.
<input type="text" id="name"
       name="name" required
       minlength="2">

<input type="email" id="email"
       name="email" required>

<input type="text" id="zip"
       pattern="[0-9]{6}"
       placeholder="6-digit PIN code">
<textarea> M3
A multi-line text input. Unlike <input>, it has an opening and closing tag. Use for messages, comments, long descriptions. Resizable by the user by default.
When: Any input longer than one line — messages, feedback, bio fields. Always pair with a <label>.
<label for="msg">Your Message</label>
<textarea id="msg" name="message"
          rows="5" minlength="10"
          required></textarea>
<select> / <option> M3
A dropdown menu. <select> is the container; each <option> is one choice. The value attribute on each option is what gets sent to the server — it can differ from the displayed text.
Attributes
id / nameOn <select> — links to label and identifies field on submit.
valueOn <option> — the data sent to the server when this is chosen.
When: A fixed set of choices (5+ items). Under 4 choices, consider radio buttons instead.
<label for="reason">Reason for contact</label>
<select id="reason" name="reason">
  <option value="job">Job opportunity</option>
  <option value="collab">Collaboration</option>
  <option value="other">Other</option>
</select>
<button> M3
A clickable button. Inside a form, type="submit" submits the form. Always use a real <button> or <a> for interactive elements — never a <div> pretending to be clickable.
type Attribute Values
submitSubmits the parent form. Default inside a form.
buttonDoes nothing by default — use with JavaScript.
resetClears all form fields back to default values.
Rule: Always set type explicitly. Real buttons are keyboard-focusable automatically. <div>s are not.
<!-- Inside a form -->
<button type="submit">Send Message</button>

<!-- Standalone (used with JS) -->
<button type="button">Load More</button>

Media & Embeds

<video> M4
Embeds a video file you own. Use for demo videos, project recordings, or any video file in your project folder. The controls attribute shows play/pause/volume to the user.
Attributes
controlsShows browser's built-in play/pause/volume controls. Always include.
widthDisplay width in pixels. Use CSS for responsive sizing.
autoplayAuto-starts. Must be combined with muted — browsers block unmuted autoplay.
loopReplays continuously when it ends.
When: A video file you have locally. Use <iframe> for YouTube/Vimeo. Include a <source> child for the file path.
<video controls width="400">
  <source src="videos/demo.mp4"
          type="video/mp4">
  Your browser doesn't support video.
</video>
<audio> M4
Embeds an audio file. Works identically to <video> but for sound — music, podcasts, voice recordings. Add controls so users can play/pause.
Attributes
controlsShows play/pause/volume. Always include.
loopReplays when finished.
When: Audio files you own — .mp3, .ogg, .wav. Use a <source> child for the file path.
<audio controls>
  <source src="audio/intro.mp3"
          type="audio/mpeg">
  Your browser doesn't support audio.
</audio>
<source> M4
Specifies the media file inside a <video> or <audio>. Self-closing. You can add multiple <source> elements with different formats — the browser picks the first one it supports.
Attributes
srcPath to the media file. Relative path like videos/demo.mp4.
typeMIME type: "video/mp4", "audio/mpeg", "video/webm", etc.
When: Always used inside <video> or <audio>. The fallback text after it shows if no format is supported.
<video controls>
  <source src="demo.mp4" type="video/mp4">
  <source src="demo.webm" type="video/webm">
  <!-- Fallback text below -->
  Video not supported.
</video>
<iframe> M4
Embeds another website's page inside yours — YouTube videos, Google Maps, Figma prototypes, Codepen demos. Always give it a title for screen readers.
Attributes
srcThe URL to embed. For YouTube use the /embed/VIDEO_ID format.
width / heightDisplay dimensions in pixels. 16:9 ratio: e.g. 560×315.
titleRequired for accessibility. Describes what's embedded.
allowfullscreenLets the user go fullscreen. Standard for video embeds.
When: Embedding YouTube demos, maps, or other third-party content. Check the site's embed policy — not every site allows it.
<iframe
  src="https://www.youtube.com/embed/dQw4w9WgXcQ"
  width="560" height="315"
  title="Project demo video"
  allowfullscreen
></iframe>
